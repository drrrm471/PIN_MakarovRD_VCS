## 3. ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

### 3.1. Git Hooks

Git Hooks — это скрипты, которые автоматически запускаются при выполнении определённых Git-команд . Они делятся на два типа:

**Клиентские хуки (выполняются на локальной машине):**
- `pre-commit` — выполняется перед созданием коммита. Может предотвратить коммит при ошибках.
- `commit-msg` — выполняется после ввода сообщения коммита. Проверяет формат сообщения.
- `post-commit` — выполняется после создания коммита.
- `pre-push` — выполняется перед отправкой изменений на сервер.
- `post-checkout` — выполняется после переключения веток.

**Серверные хуки (выполняются на сервере GitLab):**
- `pre-receive` — перед получением изменений на сервер.
- `post-receive` — после получения изменений.

В GitLab серверные хуки заменяются на **GitLab CI/CD** и **Push Rules**.

### 3.2. GitLab CI/CD

GitLab CI/CD — встроенная система непрерывной интеграции и доставки . Пайплайн описывается в файле `.gitlab-ci.yml`.

**Ключевые понятия:**
- **Pipeline** — последовательность стадий (stages).
- **Job** — задача, выполняемая в рамках стадии.
- **Stage** — группа задач, выполняемых параллельно.
- **Runner** — агент, который выполняет задачи (shared / specific).

**Базовый синтаксис `.gitlab-ci.yml`:**

```yaml
stages:
  - test
  - build

variables:
  APP_VERSION: "1.0.0"

before_script:
  - echo "Начинаем сборку..."

test_job:
  stage: test
  script:
    - echo "Запускаем тесты..."
    - ./run_tests.sh
  only:
    - merge_requests

build_job:
  stage: build
  script:
    - echo "Сборка приложения..."
  artifacts:
    paths:
      - dist/
  only:
    - main
```

#### Шаг 2. Создание pre-commit хука для проверки синтаксиса

Перейдите в директорию хуков и создайте скрипт:

```bash
cd .git/hooks
```

**pre-commit** (проверка синтаксиса Python-файлов):

```bash
cat > pre-commit << 'EOF'
#!/bin/bash

echo "🔍 Проверка синтаксиса Python-файлов..."

# Находим все .py файлы в staged-области
STAGED_PYTHON_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep '\.py$')

if [ -z "$STAGED_PYTHON_FILES" ]; then
    echo "✅ Python-файлы не найдены. Пропускаем проверку."
    exit 0
fi

# Проверяем синтаксис каждого файла
ERRORS=0
for FILE in $STAGED_PYTHON_FILES; do
    if [ ! -f "$FILE" ]; then
        continue
    fi
    echo "Проверка: $FILE"
    python3 -m py_compile "$FILE" 2>/dev/null
    if [ $? -ne 0 ]; then
        echo "❌ Синтаксическая ошибка в $FILE"
        python3 -m py_compile "$FILE"
        ERRORS=1
    fi
done

if [ $ERRORS -eq 1 ]; then
    echo "❌ Коммит отклонён: исправьте синтаксические ошибки."
    exit 1
fi

echo "✅ Все Python-файлы прошли проверку синтаксиса."
exit 0
EOF

# Делаем скрипт исполняемым
chmod +x pre-commit
```

#### Шаг 3. Создание pre-commit хука для запрета секретов

Добавьте проверку на наличие паролей/секретов в коде:

```bash
cat >> pre-commit << 'EOF'

# Проверка на наличие потенциальных секретов
echo "🔍 Проверка на наличие секретов..."

STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM)

SECRET_PATTERNS=(
    "password\s*=\s*['\"][^'\"]+['\"]"
    "secret\s*=\s*['\"][^'\"]+['\"]"
    "token\s*=\s*['\"][^'\"]+['\"]"
    "api_key\s*=\s*['\"][^'\"]+['\"]"
    "PASSWORD\s*=\s*['\"][^'\"]+['\"]"
    "API_KEY\s*=\s*['\"][^'\"]+['\"]"
)

FOUND_SECRET=0
for FILE in $STAGED_FILES; do
    if [ ! -f "$FILE" ]; then
        continue
    fi
    for PATTERN in "${SECRET_PATTERNS[@]}"; do
        if grep -E "$PATTERN" "$FILE" > /dev/null 2>&1; then
            echo "⚠️  Обнаружен потенциальный секрет в файле: $FILE"
            grep -E -n "$PATTERN" "$FILE"
            FOUND_SECRET=1
        fi
    done
done

if [ $FOUND_SECRET -eq 1 ]; then
    echo "❌ Коммит отклонён: удалите секреты из кода."
    echo "💡 Используйте переменные окружения для хранения секретов."
    exit 1
fi

echo "✅ Проверка секретов пройдена."
EOF
```

#### Шаг 4. Создание commit-msg хука для проверки формата сообщений

```bash
cat > commit-msg << 'EOF'
#!/bin/bash

# Путь к файлу с сообщением коммита
COMMIT_MSG_FILE=$1
COMMIT_MSG=$(cat "$COMMIT_MSG_FILE")

echo "🔍 Проверка формата сообщения коммита..."

# Шаблон для Conventional Commits
# <type>(<scope>): <subject>
# feat, fix, docs, style, refactor, perf, test, chore, ci, build
PATTERN="^(feat|fix|docs|style|refactor|perf|test|chore|ci|build)(\([a-z0-9\-]+\))?: .{1,100}$"

if ! echo "$COMMIT_MSG" | head -n1 | grep -E "$PATTERN" > /dev/null; then
    echo "❌ Сообщение коммита не соответствует формату Conventional Commits."
    echo ""
    echo "Допустимые типы: feat, fix, docs, style, refactor, perf, test, chore, ci, build"
    echo "Пример: feat(auth): add login functionality"
    echo "Пример: fix: resolve null pointer exception"
    echo ""
    echo "Ваше сообщение: $COMMIT_MSG"
    exit 1
fi

echo "✅ Формат сообщения корректен."
exit 0
EOF

chmod +x commit-msg
```

```bash
# Корректный коммит
git add test.py
git commit -m "feat: add test file with proper syntax"  # ✅ Должен пройти
```

#### Шаг 7. Установка хуков для всех разработчиков

Создайте скрипт для автоматической установки хуков:

```bash
cd ~/collab-project

# Создаём скрипт установки хуков
cat > scripts/install-hooks.sh << 'EOF'
#!/bin/bash

echo "📦 Установка Git Hooks..."

# Копируем хуки из каталога .githooks в .git/hooks
if [ -d ".githooks" ]; then
    cp .githooks/* .git/hooks/
    chmod +x .git/hooks/*
    echo "✅ Хуки установлены."
else
    echo "❌ Каталог .githooks не найден."
    exit 1
fi
EOF

chmod +x scripts/install-hooks.sh
```

### Часть 2 (2 часа) — Настройка GitLab CI/CD

#### Шаг 8. Создание файла `.gitlab-ci.yml`

```bash
cd ~/collab-project
```

Создайте базовый CI/CD пайплайн:

```bash
cat > .gitlab-ci.yml << 'EOF'
# Определение стадий пайплайна
stages:
  - lint
  - test
  - build

# Переменные окружения
variables:
  PYTHON_VERSION: "3.10"

# Базовые настройки для всех задач
default:
  image: python:3.10-slim
  before_script:
    - apt-get update -qq && apt-get install -y -qq git
    - python --version
    - pip install -r requirements.txt 2>/dev/null || echo "No requirements.txt found"

# --- Job: Проверка синтаксиса ---
lint:
  stage: lint
  script:
    - echo "🔍 Проверка синтаксиса Python-файлов..."
    - find . -name "*.py" -type f -exec python3 -m py_compile {} \;
    - echo "✅ Синтаксис корректен."
  only:
    - merge_requests
    - main
    - develop

# --- Job: Запуск тестов ---
test:
  stage: test
  script:
    - echo "🧪 Запуск тестов..."
    - |
      if [ -f "test.py" ]; then
        python3 test.py
        echo "✅ Тесты пройдены."
      else
        echo "⚠️ Тесты не найдены."
      fi
  only:
    - merge_requests
    - main

# --- Job: Сборка приложения (для main) ---
build:
  stage: build
  script:
    - echo "📦 Сборка приложения..."
    - mkdir -p dist
    - echo "App version: $APP_VERSION" > dist/version.txt
    - echo "Build date: $(date)" >> dist/version.txt
  artifacts:
    paths:
      - dist/
    expire_in: 30 days
  only:
    - main

# --- Job: Отчёт о покрытии ---
coverage:
  stage: test
  script:
    - echo "📊 Проверка покрытия кода..."
    - pip install coverage 2>/dev/null || true
    - coverage run -m unittest discover 2>/dev/null || echo "No unit tests"
    - coverage report 2>/dev/null || echo "Coverage report not available"
  coverage: '/TOTAL\s+\d+\s+\d+\s+(\d+\.\d+%)/'
  only:
    - merge_requests
EOF
```

#### Шаг 9. Создание тестового файла

```bash
cat > test.py << 'EOF'
#!/usr/bin/env python3
"""
Тестовый модуль для проверки CI/CD.
"""

def test_addition():
    """Тест сложения"""
    assert 1 + 1 == 2
    print("✅ test_addition passed")

def test_subtraction():
    """Тест вычитания"""
    assert 2 - 1 == 1
    print("✅ test_subtraction passed")

if __name__ == "__main__":
    print("🧪 Running tests...")
    test_addition()
    test_subtraction()
    print("✅ All tests passed!")
EOF

chmod +x test.py
```

## 6. ЧАСТЫЕ ОШИБКИ И ИХ РЕШЕНИЕ

| Ошибка | Причина | Решение |
|:---|:---|:---|
| `pre-commit: Permission denied` | Файл хука не исполняемый | `chmod +x .git/hooks/pre-commit` |
| `No such file or directory` в хуках | Неверный путь или шебанг | Проверьте `#!/bin/bash` в начале скрипта |
| Pipeline не запускается | Файл `.gitlab-ci.yml` не в корне репозитория | Переместите файл в корень проекта |
| `ERROR: Job failed: ...` | Ошибка в скрипте или зависимости | Проверьте логи джобы в GitLab |
| GitLab Runner недоступен | Используются shared runners, но они заняты | Подождите или используйте specific runner |
| `Only allowed to merge when pipeline succeeds` | Защита ветки настроена | Исправьте ошибки в пайплайне |
| Хуки не применяются после клонирования | Хуки не хранятся в репозитории | Используйте скрипт `install-hooks.sh` после клонирования |

## 7. ГЛОБАЛЬНЫЕ ХУКИ

Для установки хуков для всех репозиториев текущего пользователя:

```bash
# Создание глобальной папки для хуков
mkdir -p ~/.git-templates/hooks

# Копирование хуков в глобальную папку
cp .git/hooks/pre-commit ~/.git-templates/hooks/
chmod +x ~/.git-templates/hooks/pre-commit

# Настройка Git на использование глобальных хуков
git config --global init.templateDir ~/.git-templates

# При инициализации новых репозиториев хуки будут копироваться
git init new-project  # хуки будут скопированы автоматически
```

## 8. СОВРЕМЕННЫЕ ИНСТРУМЕНТЫ ДЛЯ ХУКОВ

Вместо написания собственных скриптов можно использовать готовые инструменты:

| Инструмент | Назначение |
|:---|:---|
| **pre-commit** (Python) | Менеджер мультиязычных pre-commit хуков |
| **lefthook** | Быстрый менеджер хуков с параллельным выполнением |
| **husky** | Популярный инструмент для JavaScript-проектов |
| **commitlint** | Проверка формата сообщений коммитов |

Пример использования `pre-commit` (Python):

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.4.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-added-large-files
```
