## 3. ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

### 3.1. Что такое GitLab CI/CD?

GitLab CI/CD — встроенная система непрерывной интеграции и доставки, которая автоматизирует процессы разработки, тестирования и развертывания приложений . Каждый раз при отправке изменений в репозиторий GitLab автоматически запускает пайплайн, описанный в файле `.gitlab-ci.yml`.

### 3.2. Ключевые концепции GitLab CI/CD

| Понятие | Описание |
|:---|:---|
| **Pipeline (Пайплайн)** | Набор задач (jobs), объединенных в стадии (stages), которые выполняются в определенном порядке  |
| **Stage (Стадия)** | Группа джобов, которые выполняются параллельно. Стадии выполняются последовательно |
| **Job (Джоба)** | Минимальная единица выполнения в пайплайне, содержит скрипты для выполнения |
| **Runner (Раннер)** | Агент, который выполняет задачи пайплайна  |
| **Artifacts (Артефакты)** | Файлы, создаваемые джобом и передаваемые между стадиями |
| **Variables (Переменные)** | Переменные окружения для конфигурации пайплайна |
| **Cache (Кэш)** | Механизм кэширования зависимостей для ускорения сборок  |

### 3.3. Базовый синтаксис .gitlab-ci.yml

```yaml
# Определение стадий пайплайна
stages:
  - build
  - test
  - deploy

# Базовые настройки для всех джобов
default:
  image: node:18-alpine
  before_script:
    - npm install

# Джоба для сборки
build_job:
  stage: build
  script:
    - npm run build
  artifacts:
    paths:
      - dist/

# Джоба для тестирования (зависит от артефактов сборки)
test_job:
  stage: test
  script:
    - npm test
  dependencies:
    - build_job
  only:
    - merge_requests
    - main

# Джоба для развертывания (только на main)
deploy_job:
  stage: deploy
  script:
    - echo "Deploying to production..."
  only:
    - main
```

### 3.4. Merge Request Pipelines

При создании Merge Request рекомендуется запускать пайплайн именно для MR, а не для каждой ветки. Это позволяет проверить, что изменения готовы к слиянию, и избежать запуска релизных джобов в MR .

Для настройки используется ключевое слово `rules` с проверкой `CI_PIPELINE_SOURCE` :

```yaml
job_name:
  stage: test
  script:
    - echo "Running in Merge Request"
  rules:
    - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
```

## 4. ПОШАГОВАЯ ИНСТРУКЦИЯ

### Часть 1 (2 часа) — Создание базового пайплайна

#### Шаг 1. Создание проекта на GitLab

1. Войдите в GitLab.
2. Нажмите **"New project"** → **"Create blank project"**.
3. Название: `cicd-lab-work`.
4. Уровень доступа: **"Private"**.
5. Нажмите **"Create project"**.

#### Шаг 2. Клонирование репозитория

```bash
git clone git@gitlab.com:username/cicd-lab-work.git
cd cicd-lab-work
```

#### Шаг 3. Создание простого приложения (на примере Python/Flask)

```bash
cat > app.py << 'EOF'
#!/usr/bin/env python3
from flask import Flask, jsonify
import os

app = Flask(__name__)

@app.route('/')
def home():
    return jsonify({"message": "Hello, CI/CD!", "version": "1.0.0"})

@app.route('/health')
def health():
    return jsonify({"status": "healthy"})

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
EOF

cat > requirements.txt << 'EOF'
flask==3.0.0
pytest==7.4.0
EOF
```

#### Шаг 4. Создание тестов

```bash
mkdir -p tests

cat > tests/test_app.py << 'EOF'
import pytest
from app import app

@pytest.fixture
def client():
    return app.test_client()

def test_home(client):
    response = client.get('/')
    assert response.status_code == 200
    data = response.get_json()
    assert data['message'] == 'Hello, CI/CD!'

def test_health(client):
    response = client.get('/health')
    assert response.status_code == 200
    data = response.get_json()
    assert data['status'] == 'healthy'
EOF
```

#### Шаг 5. Создание базового `.gitlab-ci.yml`

```bash
cat > .gitlab-ci.yml << 'EOF'
# Определение стадий пайплайна
stages:
  - build
  - test
  - deploy

# Переменные окружения
variables:
  PIP_CACHE_DIR: "$CI_PROJECT_DIR/.cache/pip"

# Кэширование для ускорения сборки
cache:
  paths:
    - .cache/pip

# --- Стадия: Сборка ---
build:
  stage: build
  image: python:3.11-slim
  script:
    - echo "📦 Установка зависимостей..."
    - pip install --cache-dir=$PIP_CACHE_DIR -r requirements.txt
    - echo "✅ Зависимости установлены"
  artifacts:
    paths:
      - venv/
    expire_in: 1 hour

# --- Стадия: Тестирование ---
test:
  stage: test
  image: python:3.11-slim
  script:
    - echo "🧪 Запуск тестов..."
    - pip install -r requirements.txt
    - python -m pytest tests/ -v --junitxml=report.xml
  artifacts:
    when: always
    reports:
      junit: report.xml
    paths:
      - report.xml
    expire_in: 1 week
  rules:
    - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

# --- Стадия: Деплой на staging ---
deploy_staging:
  stage: deploy
  image: python:3.11-slim
  script:
    - echo "🚀 Развертывание на staging..."
    - pip install -r requirements.txt
    - nohup python app.py > /tmp/flask-staging.log 2>&1 &
    - sleep 3
    - curl -sf http://localhost:5000/health
    - echo "✅ Staging deployment verified"
  environment:
    name: staging
    url: http://localhost:5000
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  when: manual
EOF
```

#### Шаг 6. Первый коммит и запуск пайплайна

```bash
git add app.py requirements.txt tests/ .gitlab-ci.yml
git commit -m "ci: add initial CI/CD pipeline"
git push origin main
```

Перейдите в GitLab → **Build** → **Pipelines** и наблюдайте за выполнением пайплайна.

### Часть 2 (2 часа) — Расширение пайплайна

#### Шаг 7. Добавление джобы для линтинга

Обновите `.gitlab-ci.yml`, добавив стадию `lint`:

```yaml
stages:
  - lint
  - build
  - test
  - deploy

# ... остальные джобы ...

lint:
  stage: lint
  image: python:3.11-slim
  script:
    - echo "🔍 Проверка стиля кода..."
    - pip install flake8
    - flake8 app.py --max-line-length=120 --statistics
  rules:
    - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

#### Шаг 8. Добавление джобы для проверки безопасности

```yaml
security_scan:
  stage: test
  image: python:3.11-slim
  script:
    - echo "🔒 Проверка безопасности зависимостей..."
    - pip install safety
    - safety check -r requirements.txt
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  allow_failure: true
```

#### Шаг 9. Настройка Merge Request pipelines

Добавьте в начало файла правило для предотвращения запуска пайплайна при создании тегов (чтобы избежать бесконечного цикла) :

```yaml
workflow:
  rules:
    - if: $CI_COMMIT_TAG
      when: never
    - when: always
```

Обновите джобы, чтобы они запускались только в нужных ситуациях :

```yaml
# Для джоб, которые должны работать в MR
rules:
  - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
  - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

# Для джоб, которые должны работать ТОЛЬКО на main (например, деплой)
rules:
  - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
    when: manual
  - when: never
```

#### Шаг 10. Создание Merge Request для проверки

```bash
git checkout -b feature/add-health-check
echo "# Health Check Endpoint" >> README.md
git add README.md
git commit -m "docs: add health check description"
git push origin feature/add-health-check
```

1. Перейдите в GitLab → **Code** → **Merge Requests** → **New merge request**.
2. Выберите `feature/add-health-check` → `main`.
3. Нажмите **"Create merge request"**.
4. Убедитесь, что пайплайн запустился и джобы выполнились успешно.

## 6. ЧАСТЫЕ ОШИБКИ И ИХ РЕШЕНИЕ

| Ошибка | Причина | Решение |
|:---|:---|:---|
| `Pipeline does not have any jobs` | Ошибка в синтаксисе `.gitlab-ci.yml` | Используйте GitLab CI Lint (Build → Pipeline Editor → Validate)  |
| `Job failed: command not found` | Команда не установлена в образе | Убедитесь, что нужные пакеты установлены в `before_script` или выбран правильный `image` |
| `Artifacts: file not found` | Путь к артефактам указан неверно | Проверьте, что файлы создаются в указанной директории  |
| Бесконечный цикл пайплайнов | Тег создаётся в джобе и триггерит новый пайплайн | Используйте `workflow: rules: - if: $CI_COMMIT_TAG when: never`  |
| Раннер недоступен | Закончились бесплатные минуты на shared runners | Используйте self-hosted runner или подождите  |
| `Only allowed to merge when pipeline succeeds` | Защита ветки требует успешного пайплайна | Исправьте ошибки в пайплайне или настройте защиту ветки |
