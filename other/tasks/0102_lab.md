## 3. ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

### 3.1. Что такое Git?

Git — распределённая система контроля версий, разработанная Линусом Торвальдсом в 2005 году. Она позволяет разработчикам:
- Сохранять историю изменений кода
- Работать с несколькими ветками одновременно
- Синхронизировать код с удалёнными репозиториями
- Совместно работать над проектами 

### 3.2. SSH-аутентификация в GitLab

SSH (Secure Shell) — протокол, обеспечивающий безопасное подключение к удалённым серверам. Для работы с GitLab вместо ввода логина и пароля при каждом push используется пара ключей: публичный (хранится на GitLab) и приватный (хранится на локальной машине) .

### 3.3. Почему GitLab?

GitLab — это DevOps-платформа, которая включает:
- Хостинг Git-репозиториев
- CI/CD для автоматической сборки и тестирования
- Инструменты для управления проектами (Issue Tracker, Wiki)
- Безопасность: защита веток, требования к прохождению CI/CD перед слиянием

В рамках курса мы используем GitLab как основную платформу для совместной разработки. Для самостоятельного ознакомления рекомендуется изучить сравнительный анализ GitHub vs GitLab (Тема 10, внеаудиторная работа).

## 4. ПОШАГОВАЯ ИНСТРУКЦИЯ

### Часть 1 (2 часа) — Установка и настройка

#### Шаг 1. Установка Git

Откройте терминал (`Ctrl+Alt+T`) и выполните:

```bash
# Обновление списка пакетов
sudo apt update

# Установка Git
sudo apt install git -y

# Проверка установки
git --version
```

Ожидаемый вывод: `git version 2.30.2` или новее .

**Что делать, если возникла ошибка?**  
Если команда `sudo apt update` завершается с ошибкой, проверьте подключение к интернету и файл `/etc/apt/sources.list`. При ошибках с GPG-ключами используйте:
```bash
sudo apt-get install --reinstall ca-certificates
sudo apt-get update
```

---

#### Шаг 2. Настройка пользователя Git

Настройте ваше имя и email — они будут привязываться к каждому коммиту :

```bash
git config --global user.name "Иванов Иван"
git config --global user.email "ivanov@example.com"
```

**Дополнительные настройки:**

```bash
# Редактор по умолчанию (nano или vim)
git config --global core.editor nano

# Цветной вывод в терминале
git config --global color.ui auto

# Просмотр всех настроек
git config --list
```

> **Важно:** Email должен совпадать с email, указанным в профиле GitLab, иначе коммиты не будут связаны с вашим аккаунтом. Ошибка "please tell me who you are" возникает именно при пропуске этого шага .

---

#### Шаг 3. Генерация SSH-ключа

Сгенерируйте новую пару SSH-ключей :

```bash
# Генерация ключа (рекомендуемый алгоритм ed25519)
ssh-keygen -t ed25519 -C "ivanov@example.com"
```

При появлении запроса:
- Нажмите `Enter` для сохранения в стандартную папку (`~/.ssh/id_ed25519`)
- При желании установите парольную фразу для дополнительной безопасности (можно оставить пустой)

**Если ваша система не поддерживает ed25519**, используйте RSA:
```bash
ssh-keygen -t rsa -b 4096 -C "ivanov@example.com"
```

**Проверка прав доступа к SSH-директории** :
```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519
```

---

#### Шаг 4. Добавление SSH-ключа в ssh-agent

```bash
# Запуск ssh-agent в фоне
eval "$(ssh-agent -s)"

# Добавление приватного ключа
ssh-add ~/.ssh/id_ed25519
```

#### Шаг 5. Регистрация на GitLab

1. Откройте браузер и перейдите на [gitlab.com](https://gitlab.com) (или на адрес корпоративного GitLab-сервера).
2. Нажмите **"Register"** и заполните форму регистрации.
3. Подтвердите email (перейдите по ссылке из письма).
4. Запомните логин и пароль.

---

#### Шаг 6. Добавление SSH-ключа в GitLab

**Просмотр публичного ключа:**

```bash
cat ~/.ssh/id_ed25519.pub
```

Вывод будет выглядеть примерно так:  
`ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... ivanov@example.com`

**Добавление ключа в GitLab** :

1. Войдите в GitLab.
2. Нажмите на ваш аватар в правом верхнем углу → **"Preferences"**.
3. В боковом меню выберите **"SSH Keys"**.
4. Нажмите **"Add new key"**.
5. В поле "Title" введите название (например, "Debian Workstation").
6. В поле "Key" вставьте скопированный публичный ключ.
7. Нажмите **"Add key"**.

---

#### Шаг 7. Проверка SSH-подключения

```bash
ssh -T git@gitlab.com
```

Для корпоративного сервера:
```bash
ssh -T git@gitlab.example.com
```

Ожидаемый вывод: `Welcome to GitLab, @username!` .

**Если порт SSH нестандартный (например, 2222):**

Отредактируйте файл `~/.ssh/config`:
```bash
Host gitlab.example.com
    HostName gitlab.example.com
    Port 2222
```

### Часть 2 (2 часа) — Создание репозитория и работа с Git

#### Шаг 8. Создание локального репозитория

```bash
# Создание директории проекта
mkdir ~/hello-git
cd ~/hello-git

# Инициализация Git-репозитория
git init
```

После выполнения появится скрытая папка `.git` — это и есть репозиторий .

---

#### Шаг 9. Создание файла README.md

```bash
# Создание файла с описанием проекта
echo "# Hello Git — первое знакомство с системой контроля версий" > README.md
echo "" >> README.md
echo "## Описание проекта" >> README.md
echo "Этот проект создан в рамках лабораторной работы по дисциплине 'Системы контроля версий'." >> README.md
echo "" >> README.md
echo "## Автор" >> README.md
echo "Иванов Иван, группа ПИ-301" >> README.md
```

---

#### Шаг 10. Добавление файлов и создание коммита

```bash
# Проверка состояния (увидим README.md как untracked)
git status

# Добавление файла в индекс (staging area)
git add README.md

# Проверка статуса (файл стал green / staged)
git status

# Создание коммита
git commit -m "feat: add README.md with project description"
```

**Соглашение о сообщениях коммитов (Conventional Commits):**
- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — изменения в документации
- `chore:` — вспомогательные задачи

---

#### Шаг 11. Просмотр истории коммитов

```bash
# Полная история
git log

# Краткая история (в одну строку)
git log --oneline

# Графическое представление веток
git log --oneline --graph --all
```

---

#### Шаг 12. Создание удалённого репозитория на GitLab

1. Войдите в GitLab.
2. Нажмите **"New project"** → **"Create blank project"**.
3. В поле "Project name" введите: `hello-git`.
4. В поле "Project slug" автоматически подставится `hello-git`.
5. Выберите уровень доступа: **"Public"** или **"Private"**.
6. **Важно:** Снимите галочку "Initialize repository with a README" (мы уже создали README локально).
7. Нажмите **"Create project"**.

---

#### Шаг 13. Связывание локального репозитория с удалённым

```bash
# Добавление удалённого репозитория (замените username на ваш логин)
git remote add origin git@gitlab.com:username/hello-git.git

# Проверка списка удалённых репозиториев
git remote -v
```

> **Примечание для корпоративного GitLab:**  
> `git@gitlab.example.com:username/hello-git.git`

---

#### Шаг 14. Отправка изменений (push)

```bash
# Отправка ветки main в удалённый репозиторий
git push -u origin main
```

- `-u` устанавливает связь между локальной и удалённой веткой (после этого можно использовать просто `git push`)
- При первом push может появиться запрос на подтверждение хоста — введите `yes`

**Проверка:** Откройте GitLab в браузере и убедитесь, что файл README.md отображается в репозитории.

### Работа с VS Code (опционально)

#### Шаг 15. Установка VS Code

**Вариант 1: Через официальный .deb-пакет** :

```bash
# Загрузка и установка .deb
wget -qO- https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor > packages.microsoft.gpg
sudo install -o root -g root -m 644 packages.microsoft.gpg /etc/apt/trusted.gpg.d/
sudo sh -c 'echo "deb [arch=amd64,arm64,armhf signed-by=/etc/apt/trusted.gpg.d/packages.microsoft.gpg] https://packages.microsoft.com/repos/code stable main" > /etc/apt/sources.list.d/vscode.list'
sudo apt update
sudo apt install code
```

**Вариант 2: Через Snap**:
```bash
sudo snap install code --classic
```

**Вариант 3: Ручная установка**:
```bash
wget -O code.deb "https://code.visualstudio.com/sha/download?build=stable&os=linux-deb-x64"
sudo dpkg -i code.deb
```

---

#### Шаг 16. Настройка Git в VS Code

**Важно:** Запускайте VS Code от обычного пользователя, а не через `sudo` :

```bash
code ~/hello-git
```

**Если VS Code не видит Git** :

1. Проверьте путь к Git: `which git` (должен быть `/usr/bin/git`).
2. В VS Code: `Ctrl+Shift+P` → введите "Git: Commit" — должно работать.
3. Если нет: Настройки (`Ctrl+,`) → поиск `git.path` → установить `/usr/bin/git`.
4. Полностью перезапустите VS Code.

**Функции Git в VS Code:**
- Инициализация репозитория: Ctrl+Shift+P → "Git: Initialize Repository"
- Статус: вкладка "Source Control" (Ctrl+Shift+G)
- Commit: ввод сообщения в поле и нажатие Ctrl+Enter
- Push/Pull: через меню в нижней панели (значок синхронизации)

## 5. ФАЙЛ .gitignore

Создайте файл `.gitignore` в корне проекта:

```bash
echo "# Системные файлы" > .gitignore
echo ".DS_Store" >> .gitignore
echo "Thumbs.db" >> .gitignore
echo "" >> .gitignore
echo "# Временные файлы" >> .gitignore
echo "*.tmp" >> .gitignore
echo "*.log" >> .gitignore
echo "" >> .gitignore
echo "# Файлы IDE" >> .gitignore
echo ".vscode/" >> .gitignore
echo ".idea/" >> .gitignore
```

Добавьте и закоммитьте:

```bash
git add .gitignore
git commit -m "chore: add .gitignore"
git push
```

## 6. ТИПИЧНЫЕ ОШИБКИ И ИХ РЕШЕНИЕ

| Ошибка | Причина | Решение |
|:---|:---|:---|
| `please tell me who you are` | Не настроены `user.name` и `user.email`  | `git config --global user.name "..."`<br>`git config --global user.email "..."` |
| `Permission denied (publickey)` | SSH-ключ не добавлен в GitLab или не загружен в ssh-agent  | Проверьте: `ssh -T git@gitlab.com`<br>Добавьте ключ: `ssh-add ~/.ssh/id_ed25519` |
| `fatal: not a git repository` | Команда выполняется вне git-репозитория | Перейдите в папку проекта: `cd ~/hello-git` |
| `! [rejected] main -> main (fetch first)` | Удалённый репозиторий содержит изменения, которых нет локально | `git pull --rebase origin main` |
| `VS Code не видит Git` | VS Code запущен от root или Git не в PATH  | `which git` → `/usr/bin/git`<br>Настройки VS Code → `git.path` → `/usr/bin/git` |
