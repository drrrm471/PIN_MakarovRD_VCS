## 3. ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

### 3.1. Отмена изменений в Git

Git предоставляет несколько способов отмены изменений в зависимости от ситуации :

| Команда | Область действия | Изменяет историю? | Безопасность |
|:---|:---|:---|:---|
| `git reset --soft` | Отмена коммита, сохранение изменений в индексе | Да | Безопасно (локально) |
| `git reset --mixed` | Отмена коммита и индексации, сохранение в рабочей директории | Да | Безопасно (локально) |
| `git reset --hard` | Полная отмена всех изменений | Да | **Опасно** (потеря данных) |
| `git revert` | Создание обратного коммита | Нет | **Безопасно** (для общих веток) |
| `git restore` | Отмена изменений в рабочей директории | Нет | Безопасно |
| `git commit --amend` | Изменение последнего коммита | Да | Безопасно (локально) |

### 3.2. Интерактивный rebase (`git rebase -i`)

Интерактивный rebase позволяет редактировать историю коммитов . Команда открывает редактор со списком коммитов, где для каждого можно выбрать действие:

| Команда | Описание |
|:---|:---|
| `pick` (p) | Оставить коммит без изменений |
| `reword` (r) | Изменить только сообщение коммита |
| `edit` (e) | Остановиться перед коммитом для внесения правок |
| `squash` (s) | Объединить коммит с предыдущим |
| `fixup` (f) | Объединить коммит с предыдущим, отбросив его сообщение |
| `drop` (d) | Удалить коммит |
| `exec` (x) | Выполнить команду shell |

### 3.3. Золотое правило rebase

**Никогда не используйте rebase на общих ветках (main, develop).** Rebase переписывает историю, и если другие разработчики уже синхронизировались с этими коммитами, возникнут серьёзные проблемы .

#### Шаг 2. Создание рабочей ветки для экспериментов

```bash
git checkout main
git checkout -b feature/experiment
```

#### Шаг 3. Создание серии коммитов

```bash
# Создаём файлы с коммитами
echo "Первый коммит" > file1.txt
git add file1.txt
git commit -m "feat: add file1"

echo "Второй коммит" > file2.txt
git add file2.txt
git commit -m "feat: add file2"

echo "Третий коммит" > file3.txt
git add file3.txt
git commit -m "feat: add file3"

# Просмотр истории
git log --oneline
```

#### Шаг 4. Практика с `git reset`

**Soft reset (отмена коммита с сохранением в индексе):**

```bash
# Отмена последнего коммита (перемещение HEAD на один коммит назад)
git reset --soft HEAD~1

# Проверка: файл file3.txt добавлен в индекс (staged)
git status
# On branch feature/experiment
# Changes to be committed:
#   (use "git restore --staged <file>..." to unstage)
#     new file:   file3.txt

# Просмотр лога - коммит исчез из истории
git log --oneline
```

**Mixed reset (отмена коммита и индексации):**

```bash
# Возвращаемся к состоянию после трёх коммитов
git reset --hard origin/feature/experiment  # если ветка есть на сервере
# Или создаём заново
echo "Третий коммит" > file3.txt
git add file3.txt
git commit -m "feat: add file3"

# Mixed reset
git reset --mixed HEAD~1

# Проверка: файл file3.txt теперь untracked
git status
# On branch feature/experiment
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#     file3.txt
```

**Hard reset (полная отмена):**

```bash
# Создаём ещё один коммит для эксперимента
echo "Четвёртый коммит" > file4.txt
git add file4.txt
git commit -m "feat: add file4"

# Hard reset - ВНИМАНИЕ! Потеря данных!
git reset --hard HEAD~1

# Проверка: файл file4.txt исчез полностью
git status
ls -la file4.txt  # файла нет
```

> ⚠️ **Важно:** `git reset --hard` безвозвратно удаляет изменения. Используйте с осторожностью!

#### Шаг 5. Практика с `git revert`

`git revert` создаёт новый коммит, который отменяет изменения предыдущего . Это безопасно для общих веток.

```bash
# Создаём файл с содержимым
echo "Важные данные" > data.txt
git add data.txt
git commit -m "feat: add important data"

# Изменяем содержимое
echo "Испорченные данные" > data.txt
git add data.txt
git commit -m "fix: corrupt data"

# Отмена изменений через revert
git revert HEAD --no-edit

# Проверка: файл data.txt восстановлен
cat data.txt  # "Важные данные"

# История: появился новый коммит отмены
git log --oneline
```

#### Шаг 6. Практика с `git restore`

`git restore` отменяет изменения в рабочей директории или индексе.

```bash
# Изменение файла
echo "Новые изменения" >> data.txt

# Отмена изменений в рабочей директории
git restore data.txt

# Изменения отменились
cat data.txt  # "Важные данные"

# Отмена индексации (перемещение из staged в unstaged)
echo "Ещё изменения" >> data.txt
git add data.txt
git restore --staged data.txt
```

#### Шаг 7. Практика с `git commit --amend`

```bash
# Создаём коммит с опечаткой
echo "Код функции" > app.py
git add app.py
git commit -m "feat: add app fumction"

# Исправляем сообщение коммита
git commit --amend -m "feat: add app function"

# Или добавляем забытый файл
echo "# Модуль приложения" > app.py
git add app.py
git commit --amend --no-edit
```

### Часть 2 (2 часа) — Интерактивный rebase

#### Шаг 8. Создание серии коммитов для rebase

```bash
# Создаём ветку для экспериментов с rebase
git checkout main
git checkout -b feature/rebase_experiment

# Создаём историю из 5 коммитов
for i in {1..5}; do
    echo "Строка $i" >> file.txt
    git add file.txt
    git commit -m "feat: add line $i"
done

# Просмотр истории
git log --oneline -5
```

#### Шаг 9. Интерактивный rebase для изменения сообщений (`reword`)

```bash
# Rebase последних 3 коммитов
git rebase -i HEAD~3
```

В открывшемся редакторе измените первые слова команд:

```
pick abc1234 feat: add line 3
pick def5678 feat: add line 4
pick ghi9012 feat: add line 5
```

Измените на:

```
reword abc1234 feat: add line 3
reword def5678 feat: add line 4
reword ghi9012 feat: add line 5
```

Сохраните и закройте редактор. Для каждого коммита откроется редактор для изменения сообщения. Введите новые сообщения, например:
- `docs: update line 3 with description`
- `docs: update line 4 with description`
- `docs: update line 5 with description`

#### Шаг 10. Интерактивный rebase для объединения коммитов (`squash`)

```bash
# Rebase последних 5 коммитов
git rebase -i HEAD~5
```

Измените команды на:

```
pick abc1234 feat: add line 1
squash def5678 feat: add line 2
squash ghi9012 feat: add line 3
pick jkl3456 feat: add line 4
pick mno7890 feat: add line 5
```

**Что произойдёт:**
- Коммиты 1, 2, 3 объединятся в один
- Коммит 4 и 5 останутся отдельными

После сохранения откроется редактор для объединённого сообщения коммита.

#### Шаг 11. Интерактивный rebase для удаления коммитов (`drop`)

```bash
git rebase -i HEAD~5
```

Удалите строки с коммитами, которые нужно убрать, или замените `pick` на `drop`.

```
pick abc1234 feat: add line 1
pick def5678 feat: add line 2
drop ghi9012 feat: add line 3      # этот коммит будет удалён
pick jkl3456 feat: add line 4
pick mno7890 feat: add line 5
```

#### Шаг 12. Интерактивный rebase для редактирования коммитов (`edit`)

```bash
git rebase -i HEAD~5
```

Замените `pick` на `edit` для коммита, который нужно изменить:

```
edit abc1234 feat: add line 1
pick def5678 feat: add line 2
pick ghi9012 feat: add line 3
pick jkl3456 feat: add line 4
pick mno7890 feat: add line 5
```

После сохранения Git остановится перед этим коммитом. Внесите изменения:

```bash
# Изменяем файл
echo "Изменённая строка 1" >> file.txt
git add file.txt

# Продолжаем rebase
git rebase --continue
```

### Часть 3 — Работа с GitLab после изменения истории

#### Шаг 13. Принудительный push

После изменения истории локальной ветки обычный `git push` завершится ошибкой:

```bash
git push origin feature/rebase_experiment
# ! [rejected] feature/rebase_experiment -> feature/rebase_experiment (non-fast-forward)
```

Используйте принудительный push:

```bash
# Вариант 1: обычный force push
git push --force origin feature/rebase_experiment

# Вариант 2: force with lease (безопаснее)
git push --force-with-lease origin feature/rebase_experiment
```

> ⚠️ **Важно:** `--force-with-lease` безопаснее, так как проверяет, что удалённая ветка не изменилась с момента последнего fetch.

#### Шаг 14. Создание Merge Request

1. Перейдите в GitLab.
2. Создайте MR из `feature/rebase_experiment` в `main`.
3. Обратите внимание, что история коммитов теперь чистая и упорядоченная.

## 6. ЧАСТЫЕ ОШИБКИ И ИХ РЕШЕНИЕ

| Ошибка | Причина | Решение |
|:---|:---|:---|
| `error: cannot rebase: You have unstaged changes` | Есть незакоммиченные изменения | `git stash` → `git rebase -i` → `git stash pop` |
| `You are in the middle of a rebase` | Rebase прерван конфликтом | `git rebase --continue` / `--abort` / `--skip` |
| `You are not currently on a branch` | Отсоединённый HEAD | `git checkout <branch>` |
| `! [rejected] ... (non-fast-forward)` | История ветки изменена локально | `git push --force-with-lease` (только для своей ветки!) |
| После `git reset --hard` пропали файлы | Команда удалила изменения | Использовать `git reflog` для восстановления |
| Не удаётся изменить старый коммит | Rebase затрагивает общие коммиты | Согласовать с командой или использовать `revert` |

## 7. ВОССТАНОВЛЕНИЕ ПОТЕРЯННЫХ ДАННЫХ (Git Reflog)

Если вы случайно выполнили `git reset --hard` и потеряли коммиты:

```bash
# Просмотр истории всех перемещений HEAD
git reflog

# Восстановление коммита по его хешу
git checkout <commit-hash>

# Создание ветки для восстановления
git branch recovery-branch <commit-hash>
```
