## 3. ТЕОРЕТИЧЕСКОЕ ВВЕДЕНИЕ

### 3.1. Git Submodules

Git Submodules — это механизм, позволяющий включить один Git-репозиторий в качестве подкаталога в другой репозиторий . Submodules особенно полезны для управления зависимостями между проектами, общими библиотеками и утилитами.

**Основные команды:**

| Команда | Назначение |
|:---|:---|
| `git submodule add <url> <path>` | Добавление submodule в репозиторий |
| `git submodule update --init --recursive` | Клонирование всех submodules |
| `git submodule foreach <command>` | Выполнение команды в каждом submodule |
| `git submodule update --remote` | Обновление submodule до последнего коммита |

**Важные особенности:**
- Submodule всегда указывает на конкретный коммит, а не на ветку.
- При клонировании родительского репозитория submodules не загружаются автоматически.
- Изменения внутри submodule требуют отдельного коммита и push.

### 3.2. Git LFS (Large File Storage)

Git LFS — это система для управления большими файлами в Git-репозиториях . Вместо хранения бинарных файлов в репозитории, LFS хранит только указатели на файлы, а сами файлы сохраняются на удалённом сервере.

**Преимущества Git LFS:**
- Уменьшение размера репозитория.
- Увеличение скорости клонирования и fetch-операций.
- Поддержка файлов любого размера.

**Основные команды:**

| Команда | Назначение |
|:---|:---|
| `git lfs install` | Инициализация LFS в репозитории |
| `git lfs track "*.psd"` | Отслеживание файлов определённого типа |
| `git lfs push --all origin` | Отправка всех LFS-файлов на сервер |

### 3.3. GitLab Container Registry

GitLab Container Registry — это встроенный реестр контейнеров, который позволяет хранить и управлять Docker-образами в рамках GitLab-проекта . Каждый проект может иметь свой собственный реестр с образами.

**Особенности GitLab Container Registry:**
- Интеграция с CI/CD для автоматической сборки и публикации.
- Контроль доступа через права GitLab.
- Поддержка тегирования и версионирования образов.
- Встроенный интерфейс для просмотра образов и тегов.

## 4. ПОШАГОВАЯ ИНСТРУКЦИЯ

### Часть 1 (2 часа) — Git Submodules

#### Шаг 1. Создание родительского репозитория

```bash
# Создание нового проекта на GitLab
# Название: parent-project

git clone git@gitlab.com:username/parent-project.git
cd parent-project

echo "# Parent Project" > README.md
echo "This project uses submodules for shared components." >> README.md

git add README.md
git commit -m "docs: initial commit"
git push origin main
```

#### Шаг 2. Создание репозитория-зависимости (submodule)

```bash
# Создание нового проекта на GitLab
# Название: shared-library

git clone git@gitlab.com:username/shared-library.git
cd shared-library

# Создаём общую библиотеку
cat > utils.py << 'EOF'
#!/usr/bin/env python3
"""
Общая библиотека утилит для всех проектов.
"""

def greet(name):
    return f"Hello, {name}!"

def add(a, b):
    return a + b

def get_version():
    return "1.0.0"
EOF

cat > README.md << 'EOF'
# Shared Library

Общая библиотека для всех проектов.

## Функции
- `greet(name)` — приветствие
- `add(a, b)` — сложение
- `get_version()` — версия библиотеки
EOF

git add .
git commit -m "feat: initial library implementation"
git push origin main
```

#### Шаг 3. Добавление submodule в родительский проект

```bash
cd ~/parent-project

# Добавление shared-library как submodule
git submodule add git@gitlab.com:username/shared-library.git libs/shared

# Проверка
git status
git submodule status
```

**Ожидаемый вывод:**
```
new file:   .gitmodules
new file:   libs/shared
```

#### Шаг 4. Коммит изменений в родительском проекте

```bash
# Добавление .gitmodules и ссылки на submodule
git add .gitmodules libs/shared
git commit -m "feat: add shared-library as submodule"
git push origin main
```

#### Шаг 5. Клонирование родительского проекта с submodule

```bash
# Тестирование клонирования
cd ~
git clone --recursive git@gitlab.com:username/parent-project.git parent-project-clone
cd parent-project-clone

# Проверка наличия libs/shared
ls -la libs/shared/
```

#### Шаг 6. Обновление submodule до последней версии

```bash
cd ~/parent-project

# Переходим в submodule
cd libs/shared

# Обновляем библиотеку
echo "def multiply(a, b): return a * b" >> utils.py
git add utils.py
git commit -m "feat: add multiply function"
git push origin main

# Возвращаемся в родительский проект
cd ../..

# Обновляем ссылку на submodule
git add libs/shared
git commit -m "chore: update shared-library submodule"
git push origin main
```

### Часть 2 (2 часа) — Git LFS в GitLab

#### Шаг 7. Установка и настройка Git LFS

```bash
# Установка Git LFS
curl -s https://packagecloud.io/install/repositories/git-lfs/git-lfs/script.deb.sh | sudo bash
sudo apt-get install git-lfs -y

# Инициализация LFS в системе
git lfs install --system
```

#### Шаг 8. Создание репозитория для LFS

```bash
# Создание нового проекта на GitLab
# Название: lfs-project

git clone git@gitlab.com:username/lfs-project.git
cd lfs-project

# Настройка LFS для отслеживания файлов изображений
git lfs install
git lfs track "*.png"
git lfs track "*.jpg"
git lfs track "*.jpeg"
git lfs track "*.gif"
git lfs track "*.psd"
git lfs track "*.zip"
git lfs track "*.mp4"
git lfs track "*.pdf"

# Добавление .gitattributes в репозиторий
git add .gitattributes
git commit -m "chore: configure Git LFS for binary files"
```

#### Шаг 9. Добавление больших файлов

```bash
# Создание тестовых файлов (имитация больших файлов)
dd if=/dev/zero of=sample.png bs=1M count=10
dd if=/dev/zero of=document.pdf bs=2M count=5

# Добавление файлов в LFS
git add sample.png document.pdf
git commit -m "feat: add sample binary files"
git push origin main
```

#### Шаг 10. Проверка LFS

```bash
# Просмотр списка LFS-файлов
git lfs ls-files

# Просмотр статуса LFS
git lfs status

# Проверка размера репозитория
du -sh .git
```

#### Шаг 11. Настройка GitLab для LFS

1. Перейдите в ваш проект на GitLab.
2. **Settings** → **Repository** → **"Large File Storage (LFS)"**.
3. Убедитесь, что LFS включен.

#### Шаг 12. Интеграция LFS с CI/CD

Добавьте в `.gitlab-ci.yml`:

```yaml
stages:
  - test
  - build

variables:
  GIT_LFS_SKIP_SMUDGE: "0"

test_lfs:
  stage: test
  image: alpine:latest
  before_script:
    - apk add --no-cache git git-lfs
    - git lfs install
    - git lfs pull
  script:
    - echo "🔍 Проверка LFS-файлов..."
    - ls -la *.png *.pdf 2>/dev/null || echo "No LFS files found"
    - echo "✅ LFS files verified"
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

### Часть 3 — GitLab Container Registry

#### Шаг 13. Создание приложения с Dockerfile

```bash
# Создание нового проекта на GitLab
# Название: container-registry-lab

git clone git@gitlab.com:username/container-registry-lab.git
cd container-registry-lab
```

Создайте простое приложение:

```bash
cat > app.py << 'EOF'
#!/usr/bin/env python3
from flask import Flask, jsonify
import os

app = Flask(__name__)

@app.route('/')
def home():
    return jsonify({
        "message": "Hello from Container Registry!",
        "version": os.environ.get('APP_VERSION', '1.0.0')
    })

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
EOF

cat > requirements.txt << 'EOF'
flask==3.0.0
EOF
```

Создайте Dockerfile:

```bash
cat > Dockerfile << 'EOF'
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

EXPOSE 5000

CMD ["python", "app.py"]
EOF
```

#### Шаг 14. Настройка CI/CD для Container Registry

```bash
cat > .gitlab-ci.yml << 'EOF'
stages:
  - build
  - test
  - publish

variables:
  APP_VERSION: "1.0.0"
  CI_REGISTRY_IMAGE: $CI_REGISTRY_IMAGE

# --- Сборка образа ---
build_image:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  script:
    - echo "📦 Building Docker image..."
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker tag $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA $CI_REGISTRY_IMAGE:latest
    - docker save $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA > image.tar
  artifacts:
    paths:
      - image.tar
    expire_in: 1 hour
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

# --- Тестирование образа ---
test_image:
  stage: test
  image: docker:latest
  services:
    - docker:dind
  script:
    - echo "🧪 Testing image..."
    - docker load < image.tar
    - docker run -d -p 5000:5000 --name test-app $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - sleep 5
    - curl -sf http://localhost:5000/ || exit 1
    - echo "✅ Image test passed"
  dependencies:
    - build_image
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"

# --- Публикация образа в Container Registry ---
publish_image:
  stage: publish
  image: docker:latest
  services:
    - docker:dind
  script:
    - echo "📤 Publishing image to Container Registry..."
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker load < image.tar
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - docker push $CI_REGISTRY_IMAGE:latest
    - echo "✅ Image published"
  dependencies:
    - build_image
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

# --- Деплой с использованием образа из Container Registry ---
deploy_staging:
  stage: publish
  image: docker:latest
  services:
    - docker:dind
  script:
    - echo "🚀 Deploying from Container Registry..."
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker pull $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - docker run -d -p 5000:5000 --name deploy-test $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - sleep 3
    - curl -sf http://localhost:5000/ || exit 1
    - echo "✅ Deployment successful"
  environment:
    name: staging
    url: http://localhost:5000
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
EOF
```

#### Шаг 15. Коммит и проверка

```bash
git add .
git commit -m "ci: add Container Registry with CI/CD integration"
git push origin main
```

1. Перейдите в GitLab → **Deploy** → **Container Registry**.
2. Вы должны увидеть опубликованный образ.

#### Шаг 16. Работа с LFS и Container Registry в одном проекте

Объединённый `.gitlab-ci.yml`:

```yaml
stages:
  - lfs_check
  - build
  - test
  - publish

variables:
  APP_VERSION: "1.0.0"
  CI_REGISTRY_IMAGE: $CI_REGISTRY_IMAGE
  GIT_LFS_SKIP_SMUDGE: "0"

# --- Проверка LFS-файлов ---
check_lfs:
  stage: lfs_check
  image: alpine:latest
  before_script:
    - apk add --no-cache git git-lfs
    - git lfs install
    - git lfs pull
  script:
    - echo "🔍 Checking LFS files..."
    - git lfs ls-files || echo "No LFS files tracked"
    - echo "✅ LFS check complete"
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

# --- Сборка и публикация образа ---
build_and_publish:
  stage: build
  image: docker:latest
  services:
    - docker:dind
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```

## 6. СРАВНЕНИЕ SUMMODULES И SUBTREE

| Критерий | Submodules | Subtree |
|:---|:---|:---|
| **Хранение** | Указатель на внешний репозиторий | Копия кода в основном репозитории |
| **История** | История хранится отдельно | История объединена |
| **Клонирование** | Требуется `--recursive` | Всё включено |
| **Работа с изменениями** | Требуется коммит в submodule и обновление ссылки | Изменения коммитятся напрямую |
| **Управление** | Сложнее, требуется понимание | Проще, как с обычным кодом |

Команда для добавления subtree:

```bash
git subtree add --prefix=libs/shared git@gitlab.com:username/shared-library.git main --squash
```

## 7. ЧАСТЫЕ ОШИБКИ И ИХ РЕШЕНИЕ

| Ошибка | Причина | Решение |
|:---|:---|:---|
| `No submodule mapping found` | Submodule добавлен, но не инициализирован | `git submodule update --init` |
| `git-lfs: command not found` | Git LFS не установлен | `sudo apt-get install git-lfs` |
| `Git LFS: object not found` | Файл не загружен на сервер | `git lfs push --all origin` |
| `denied: requested access to the resource is denied` | Нет прав на Container Registry | Проверьте права пользователя в проекте |
| `File is 150.00 MB, which exceeds the limit` | Превышен лимит LFS | Проверьте настройки лимитов в GitLab  |
| Submodule обновляется, но изменения не видны | Не обновлена ссылка в родительском проекте | `git add <submodule>; git commit` |
